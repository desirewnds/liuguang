# macOS 桌面版

本工程将同一套 Rust/Iced 界面和下载核心用于 Windows、Apple Silicon Mac 和 Intel Mac。网页版保持独立。Mac 页面保留暖灰、砖红、灰蓝配色，以及合集选集、原始集号、画质、大小估算、高级参数、预设、任务历史和 CLI。

## 当前状态与验证边界

Apple Silicon 与 Intel 的平台适配及独立打包流程已实现。当前尚未完成 macOS 目标编译，没有生成可交付的 Mac 二进制或 DMG，也没有实机运行结果。下文说明实现目标和构建方法，不代表这些功能已经在 Mac 上验证。

桌面版源码发布于 [desirewnds/liuguang](https://github.com/desirewnds/liuguang)，应用本体采用 Apache-2.0。共享代码已通过单任务、低优先级 Windows 编译检查；Windows 的实际安装、升级、卸载及完整界面验收仍未完成。

## 使用目标

- Apple Silicon 与 Intel 分别提供与其架构匹配的 `.app` 和 DMG，不要求用户安装 Rosetta 作为运行前提。
- yt-dlp、FFmpeg、FFprobe、Node 和必要动态库随包携带；普通使用无需 Homebrew、系统 Python、Rust、Node 或 FFmpeg。
- 下载视频仍需要能够访问目标网站的网络；登录内容可能需要用户明确提供 Cookies，额外外部下载器及插件由用户选择提供。
- 最低 macOS 版本以依赖清单、实际 Mach-O 最低版本和构建设置中要求最高者为准；未完成该检查前不声称支持某个最低系统版本。
- 不上架 App Store。Developer ID 签名与 Apple 公证是可选发布流程，不以付费开发者会员作为源码构建前提。未公证分发需如实说明 Gatekeeper 可能阻止首次启动，不要求关闭系统安全功能。

## 程序、依赖与数据

应用布局：

    流光.app/
      Contents/
        Info.plist
        MacOS/flow-desktop
        MacOS/flow-cli
        Resources/engine/

平台使用同一个 `engine_directory` 入口定位资源。GUI 与 CLI 通过绝对路径调用随包组件，不依赖全局 PATH。缓存和可更新的私有引擎位于用户自己的应用目录，不改写应用包中的基础运行资源。

配置、预设、历史及窗口状态使用用户的 `Library/Application Support` 下流光专属目录；可丢弃缓存和会话临时数据使用 `Library/Caches` 下流光专属目录；视频默认使用用户的 `Movies/流光`，也可选择其他视频目录。应用数据与视频不得重叠，清理只能作用于归属明确的应用文件。

Mac 路径比较保留大小写，不沿用 Windows 的全路径小写规则；系统自带的 `/var`、`/tmp` 别名与用户目录中的任意符号链接分开处理。应用不会扫描浏览器凭据或本机代理端口。

Mac 设置页实现了“清理应用数据并退出”：确认后停止应用管理的下载并退出，由应用内的 CLI 助手等待 GUI 进程结束、其他 CLI 释放数据，再在排他锁保护下清理。缺少归属证明、遇到外来文件或占用超时会保留数据并报告，不杀死另一个 CLI。视频目录始终受保护。直接把 `.app` 移入废纸篓不会自动运行清理；需要清理数据时先在设置中执行，再移除应用。此流程尚未在 Mac 上实测。

## 平台体验

界面布局与下载语义共用。Mac 使用系统字体、Command 快捷键、Dock 和菜单栏入口；关闭窗口与真正退出分开，真正退出时回收整个下载子进程组。文件选择、Finder 定位和通知由 Mac 平台实现。AppKit 对象限定在主线程，网络、哈希、数据库和媒体工作不放到界面线程执行。

每个平台的媒体工具来自独立锁定的发行产物。平台间硬件编码器、驱动和第三方 FFmpeg 构建配置可能不同，不能宣称全部 FFmpeg 能力枚举完全一致。打包需核对流光功能要求的编解码、容器、字幕和协议能力，具体版本及来源见 Mac 打包材料。

## 构建与发布原则

Mac 构建在 macOS 上完成；两个目标分别为 `aarch64-apple-darwin` 和 `x86_64-apple-darwin`。构建缓存、下载归档和临时文件都留在工程内；不执行 Homebrew 安装，不改全局 PATH，不安装常驻服务。

默认单个构建任务、串行短时检查，不运行持续负载或压力测试。Mac CI 需要维护者手动启动，不会因 push 自动构建或发布。签名凭据不进入源码、安装包或日志。

发行附件应包含对应架构成品、校验和、依赖与构建清单，以及匹配版本的第三方许可/源码材料获取说明。Mac 许可证索引必须按 Mac 目标生成，不能直接把 Windows 依赖索引当成 Mac 审查结果。
