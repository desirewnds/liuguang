# 用户指南

## 添加下载

1. 打开“添加下载”，粘贴一个或多个视频链接并解析。
2. 同时带有视频和合集信息的链接，先确认下载范围。纯合集会显示选集列表。
3. 在列表中选择条目。原始集号不因搜索或排序改变；例如 B 站 `p=7` 对应原始第 7 P。
4. 直接选择画质、格式、保存位置，检查数量和大小后提交。

GUI 新下载默认放到 Windows“视频”文件夹下的“流光”，通常是 `Videos/流光`；系统视频文件夹被重定向时使用实际位置。无法取得视频文件夹时，依次使用系统下载文件夹或用户主目录下的 Videos。旧版视频不会搬移，历史仍保留原文件位置。

“最佳”选择当前账户与网络条件下源站实际提供的最佳可用格式。选定 1080p 等具体分辨率时，默认不会悄悄降级；若愿意接受较低画质，在设置中启用自动降低分辨率。最高可用格式也可能受登录、会员权限、地区及源站策略影响。

自动格式保留适合的源编码，画质优先级与 MP4/H.264 偏好分开。选择音频格式会走音频提取流程；重封装与转码是不同操作，转码需要时间且可能改变画质。

合集条目逐步读取。未完成读取时，“已读取”不是合集总数；取消读取后不能把尚未读取的内容当作不存在。搜索只过滤显示结果，不清空其他已选条目。合集里的每集实际可用画质可能不同。

## 大小与进度

已知大小来自源站提供的流大小，估算值由可用码率和时长等信息计算。无法估算时显示未知；部分条目已知时不能把小计看作完整总量。改动格式或认证设置后需要重新估算。

下载通常包含独立视频和音频流，还会生成合并临时文件，因此峰值磁盘占用可能高于最终文件大小。合并、转码没有可靠百分比时只显示处理阶段。完成后的实际大小以最终文件为准。

## 高级设置

常用控件旁的“高级设置”进入同一工作面板。可按中文名称、用途、原始参数及别名搜索；“已修改”便于检查本次覆盖。未设置与显式关闭不同：未设置沿用常用设置和引擎默认行为。

普通选项使用开关、下拉框或数值/文本输入。可重复参数逐条添加。文件名模板、格式表达式、筛选表达式保留原生语法并提供示例。只需要修改的项才添加覆盖。

“应用”回到本次下载草稿；“保存为默认”影响后续新任务；预设保存一组可重复使用的配置。已创建任务保留自己的配置快照。查询、模拟、自定义标准输出、缓存维护等独立命令在“工具”运行，避免破坏普通任务进度协议。

## 任务与退出

下载中显示排队、下载和处理状态，历史可筛选完成、失败、取消或中断记录。合集父行表示本次下载批次，子行显示具体视频及原始集号。

取消会停止任务子进程。重试默认使用任务创建时的配置；使用当前设置重试会更换该次配置。是否能从临时文件续传由源站、下载格式和保留文件决定。移除任务记录与删除视频文件不是同一操作。

关闭窗口默认进入系统托盘，任务继续。托盘图标可重新打开窗口；托盘菜单“退出”会提示活动任务影响并保存状态。重新启动后中断任务由你决定是否恢复。设置中的关闭行为可改为关闭即退出。

## 网络和登录

- 继承环境代理：由引擎使用可用的环境代理配置，不扫描代理软件或端口。
- 直接连接：明确关闭引擎代理。
- 自定义代理：只使用你填写的代理地址。应用不提供或搜索免费代理节点。

代理、超时、限速、任务并发和分片并发是不同设置。下载慢时先查看错误和速度，再调整适合当前网络的设置；过高并发可能触发源站限流。

需要登录时可明确选择 Netscape Cookies 文件或浏览器来源；未选择时不会主动读取浏览器登录信息。Cookies 相当于登录凭据，避免分享。配置导出默认排除认证信息和原始参数；任何拟公开日志仍应先检查内容。

## 命令行与工具

原生安装包包含 Iced 界面及随包下载、媒体和 JavaScript 运行组件，不需要 WebView2 或系统共享 Node/FFmpeg。组件许可与来源记录保存在随包许可目录。普通 GUI 操作不会弹出命令窗口。

“工具”保留 yt-dlp 原生参数能力，不需要普通用户看到命令窗口。复杂参数可输入 JSON 字符串数组，避免路径引号歧义，例如 `["--version"]`。运行查询命令时可查看输出；命令结果不冒充普通下载任务的可靠进度。

独立 `engine/yt-dlp.exe` 仍保留。直接调用原始 EXE 时遵循 yt-dlp 自身的环境和缓存规则，不经过 `flow.cmd` 的私有副本及临时目录管理。高级外部下载器和第三方插件由你明确提供路径，安装包不会捆绑所有生态依赖。

安装目录的 `flow.cmd` 是已配置依赖路径的命令行入口，在 PowerShell 中可运行：

```powershell
./flow.cmd --version
./flow.cmd -F "视频链接"
./flow.cmd -P "D:\Videos" "视频链接"
./flow.cmd -U
```

入口使用随包 FFmpeg、Node 和插件，并忽略自动查找的原生配置文件。它独立于桌面界面的默认设置；需要代理、登录或特定命名规则时，在命令中明确填写。未指定 `-P` 时，CLI 遵循 yt-dlp 的当前工作目录输出规则，不套用 GUI 的 Videos/流光 默认目录。显式提供的 `--config-locations` 仍遵循 yt-dlp 原生规则。

首次运行 `flow.cmd` 会把随包 yt-dlp 复制到 `%LOCALAPPDATA%/org.flowdown.desktop/shell-v2/cli-engine/yt-dlp.exe`，以后使用该副本。`-U` 或 `--update-to` 只更新 CLI 私有副本；GUI 更新自己的引擎，两边互不自动同步。FFmpeg、Node 和插件仍来自安装包。出现版本差异时，分别检查 GUI 引擎信息与 `flow.cmd --version`。

使用 `-o -` 等输出媒体二进制数据的功能时，请使用 `flow.cmd`。GUI 工具只呈现 UTF-8 文本，会归一换行，标准错误用于脱敏诊断；它不保证按原始字节输出。需要二进制重定向或管道时，应选择能保持二进制内容的终端和目标程序。

## 数据位置与升级

以下默认路径和安装器行为适用于 Windows。Mac 的独立应用包、应用数据和视频位置见 [macOS 桌面版](macos.md)；Mac 构建与实机验证状态分别记录。

| 内容 | 默认位置 |
| --- | --- |
| GUI 视频 | Windows 视频文件夹下的“流光” |
| 配置、预设、历史、任务日志、GUI 引擎副本 | `%APPDATA%/org.flowdown.desktop/managed-v2/` |
| GUI 引擎缓存与临时文件 | 上述目录中的 `cache/`、`runtime/` |
| 窗口状态、CLI 缓存和临时文件 | `%LOCALAPPDATA%/org.flowdown.desktop/shell-v2/` |
| CLI yt-dlp 私有副本 | 上述目录中的 `cli-engine/` |

升级会把可识别的旧设置与历史导入新受管目录，视频留在原处。旧任务仍保留原配置；如果旧保存位置属于应用数据目录，改选独立视频目录后使用“按当前设置重试”。清理按目录所有权和已记录的文件指纹判断，不按视频扩展名猜测哪些文件应保留。

开发或验证时，`FLOW_DATA_DIR` 仍只覆盖核心数据根，不是完整隔离模式。完整验证须同时设置 `FLOW_ROAMING_DATA_DIR`、`FLOW_LOCAL_DATA_DIR`、`FLOW_DOWNLOAD_DIR` 为独立的绝对路径，并按需设置 `FLOW_DATA_DIR`。不完整的新覆盖组合会拒绝初始化；隔离模式不注册正式托盘、通知或系统文件对话框。不要把个人资料目录当作应用私有目录。

## 卸载与保留文件

本节的安装器选项适用于 Windows。Mac 在设置里使用“清理应用数据并退出”，完成后再把应用移入废纸篓；直接移入废纸篓会保留配置和缓存。Mac 清理会等待 GUI 和 CLI 退出，只处理归属明确的应用数据，视频保留；实际运行状态见 [macOS 记录](macos.md)。

卸载默认选择“删除流光设置、历史和缓存（保留视频）”。取消该选项会保留设置、历史和私有引擎，但仍清理应用可丢弃的缓存和临时文件。静默参数 `/KEEPDATA` 与 `/DELETEAPPDATA` 分别对应这两种选择；同时传入时 `/KEEPDATA` 优先。正常升级不会执行这段数据清理。

旧版数据库、任务日志、引擎和已识别的旧 WebView2 文件，只有属于记录清单且文件指纹仍匹配时才会清理。未知文件、已改变的旧文件、旧版共享的全局 yt-dlp 缓存，以及你明确指定的外部目录均保留。安装目录内不属于本包清单的文件保留；目录非空时不强行删除。

找不到所有权证明、发现目录联接或有文件被占用时，清理可能停止并提示重试。先关闭流光及 CLI，再处理提示，不要自行递归删除整个 AppData 目录。卸载会尝试按流光的应用 ID 清理系统通知历史，但 Windows 的诊断、事件、使用记录等由系统维护，不能保证系统“零痕迹”。

原生迁移的实际验证状态见 [重写记录](native-rewrite-status.md)。按用户要求，安装、覆盖安装、升级及卸载不在日常工作电脑实测；隔离 Windows 实测仍未完成。历史结果见 [1.0.1 验证记录](verification-1.0.1.md)，不能当作原生版重测。
