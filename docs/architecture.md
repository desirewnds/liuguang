# 原生桌面架构

流光 2.0 使用 Rust + Iced。下载核心复用已有 flow-core，界面与系统集成独立迁移；父目录网页版的源码、启动方式、数据库和凭据保持独立。当前版本仍在验证，状态见 native-rewrite-status.md。

macOS 适配复用上述界面、事件和下载核心，平台外壳、进程组、数据目录及发行清单分别实现。Apple Silicon 与 Intel 采用独立运行依赖及应用包。Windows 既有成品不被 Mac 开发覆盖；Mac 源码、构建和运行状态见 [macOS 记录](macos.md)。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| flow-gui | Iced 视图、主题、草稿、选集、键盘和纯界面模型 |
| flow-app | 原生应用入口、命令派发、有界事件、退出协调 |
| flow-core | 解析、估算、参数、队列、SQLite、引擎和输出校验 |
| flow-platform | 私有路径、窗口、托盘、通知、文件对话框、安装生命周期 |
| flow-cli | 独立原生参数与字节流入口 |
| packaging | 独立 NSIS、资源归属清单、发布校验 |

GUI 通过命令及结构化事件调用核心，不直接操作 SQLite，不直接启动媒体程序。核心不依赖 Iced。flow-gui 的 model 是独立库，不启用 desktop feature 时可单独验证。Iced 运行时采用两个异步工作线程、最多八个阻塞工作线程；窗口事件和布局不执行网络、文件哈希或图片解码。

## 数据流与性能

核心事件先进入 flow-app 的有界收件箱。同任务只保留最新状态；进度最多约每 100 ms 提交一次，完成、失败、设置和外壳事件及时唤醒。任务事件积压时要求重新获取权威快照，而不是无限持有整个历史。状态带单调版本，迟到的进度不能覆盖较新的完成状态。

预览进度是追加批次。中间队列溢出只影响渐进显示，不限制最终合集数量；最终成功响应才确定完整可选集合。每个预览、估算和图片上下文都有代次，取消或更改设置后的旧结果被丢弃。不能把部分目录当成完整合集提交。

列表只构建可见行；进度变化不反复重建全部成员关系。图片限制请求大小、解码尺寸、缓存和并发，切换代理后清掉旧上下文。代理解析复用下载核心的高级/原始参数解析，不把另一个参数的值误认成选项，也不扫描代理软件或端口。

任务进度不逐帧写数据库；持久状态与配置快照由核心维护。诊断日志按需读取，并做脱敏及容量限制。性能数字必须来自真实构建和短时测量，不能从选择 Rust 或 Iced 推导。

## 下载语义

指定清晰度默认要求精确匹配，自动降低分辨率需要显式启用。“最佳”与容器/编码偏好分开。已知大小、估算、未知与处理阶段分别表示；不把视频单流大小或部分条目小计当成完整总量。

集合 ID、批次 ID、任务 ID、原始条目 ID 分开。多链接按来源批次提交，每组有稳定的幂等请求 ID；部分提交失败保留未提交部分。合集搜索、显示排序和虚拟化不改变源站原始集号。

暂停队列只阻止启动后续任务，运行中的下载继续。取消由核心决定终态。重试默认使用原配置；按当前设置重试需要明确操作。移除记录不删除视频。重启后未完成任务恢复为中断，等待用户重试。

高级参数按目录驱动控件。未设置、启用和显式负向选项不能混为一谈；false/null 不代表自动启用反向选项。命令专用模式进入工具或 CLI，普通下载不能静默忽略它们。

## 路径、系统集成与退出

应用标识沿用 org.flowdown.desktop。配置、历史、日志、GUI 引擎及缓存进入 Roaming AppData 下 managed-v2；窗口状态、CLI 副本及缓存进入 Local AppData 下 shell-v2。视频默认在系统视频文件夹的“流光”目录，路径与应用私有树不得重叠。GUI/CLI 只为自己的进程设置 TEMP、TMP 和依赖路径，不改全局环境。

FLOW_DATA_DIR 保持旧的“仅覆盖核心根目录”语义，不是完整便携模式。完整验证同时设置 FLOW_ROAMING_DATA_DIR、FLOW_LOCAL_DATA_DIR、FLOW_DOWNLOAD_DIR 为相互独立的绝对路径，并按需设置 FLOW_DATA_DIR。不完整的新覆盖组合会拒绝初始化。隔离模式禁用正式托盘、通知、系统文件对话框和 Explorer 操作，避免测试留下对应系统记录。

单实例在数据库打开前建立。系统消息线程处理托盘和有界通知；下载回调不会阻塞等待通知。只有托盘成功建立时关闭窗口才可隐藏；没有托盘时走退出流程。退出确认后回收 Job Object 管理的子进程树，并保存中断状态。窗口状态保留正常尺寸、位置、最大化状态与位置缩放，恢复时处理离屏和多显示器边界。

## 引擎和安装生命周期

原生包包含 yt-dlp、Node、FFmpeg、FFprobe 和七个私有共享 DLL，不包含 WebView2 或 Tauri。Node 用于下载引擎的 JavaScript 功能。FFmpeg 是独立进程，不作为 C 库链接到 GUI。

GUI 与 CLI 的可更新引擎副本独立；更新先校验候选，再切换并保留回退版本，不改安装资源。CLI 保留原始 stdout/stderr 字节和二进制管道；GUI 工具只展示文本及脱敏诊断。

安装器为当前用户安装。资源清单与实际编译进 CLI 的清单必须一致；暂存、恢复和提交采用明确文件归属，未知冲突文件不被认领。升级保留配置和视频。旧浏览器缓存只按明确归属清理，不整删同时包含 CLI 数据的 shell-v2。

卸载检查所有权、路径重叠、历史媒体位置、链接和占用。无法证明归属时保留并报告，不按扩展名猜测视频。Windows 自己维护的使用记录不属于应用能完全控制的范围，不承诺零痕迹。

## 支持与验证边界

当前目标 Windows x64，基础构建要求 Windows 10 22H2 或更新。已有本地工具链是 GNU；其他平台和工具链结果单独记录。真实安装、升级、卸载仍需隔离 Windows，当前按用户要求未在日常电脑实测。

本轮构建和测试保持低并发；不执行持续压力或长稳负载。真实网站的可用性取决于网络、账户、源站和引擎版本，本地合成媒体通过不代表所有站点都已验证。
